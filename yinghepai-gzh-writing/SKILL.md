# 硬核派公众号写作标准（团队共享 · 自包含版）

> 目标：让硬核派的任何一位小伙伴写公众号文章，都能达到硬核派公众号同款质量——排版、格式、内容风格完全统一。
> **本 skill 自包含**：排版组件库、校验脚本、真实范本全部打包在内，不依赖外部 skill。任何 AI 拿到即可用。

## When to Use

- 硬核派团队任何人要写公众号文章（活动回顾/工具推荐/人物采访/赛事公告/合作宣传）
- 写出来的文章被评价「不像硬核派的风格」「排版不对」「内容单薄」
- 需要把活动素材（逐字稿/智能纪要/现场照片）变成公众号文章

**Don't use for：** 小红书图文、抖音脚本、飞书内部文档（各有其他 skill）

## 第一步：素材处理（写之前必须做）

1. **逐字读素材，不只看总结**——如果活动有飞书妙记/智能纪要，必须打开妙记页面看「智能章节」（每段都有详细摘要），有条件就看完整逐字稿。用户明确强调过：「一定要逐字去看，不要只看总结，要看妙记里面的逐字稿」。这是写出好内容的前提。
2. **妙记抓取方法**：见 `references/feishu-minutes-scrape.md`（Playwright 抓公开链接，API 缺 minutes 权限时替代）。
3. **提取关键信息**：活动时间地点、嘉宾名单（名字必须准确！语音转文字人名常错，以用户最终确认为准）、每个分享者的项目/主题/核心观点、现场互动、颁奖、照片素材。
4. **人名准确铁律**：语音转文字识别的人名经常错（如「韦神」变「维优」、「黄宇厦」变「黄宇尚」、「木木」实为「木晓瑾」、「冠子」实为「赛博罐子」）。写之前向用户确认准确名单，或按用户最新提供的名单为准。
5. **整理成结构化笔记**：按「开场→各分享者→现场环节→收官」的顺序整理素材，标出哪些是亮点细节（金句、数据、真实案例）。

## 第二步：确定文章类型与结构

### 类型 A：活动回顾（最常见）
**结构模板（按此顺序）：**
```
QUOTE 引言卡（金句，从活动里最有张力的一句话提炼）
前言（活动时间地点+主题+一句话概述）
01 分享者/环节（每人或每环节一小节，详写核心内容）
02 现场互动/问答（有趣的问答、现场反应）
03 颁奖/特殊环节
∞ 结语（升华主题 + 感谢主办方/嘉宾 + 引导关注）
END 线（不署名，文章到此结束）
```

### 类型 B：工具/内容推荐
```
引言卡（痛点或钩子）
01-04 每个工具：适合什么 / 内容 / 特征
结尾：引导互动（「你最想拿哪个试试？评论区告诉我」）
```

### 类型 C：人物采访/特稿
```
引言卡（被访者金句）
01 认识 TA（背景介绍）
02 成长线/经历脉络
03 方法/干货
04 快问快答
∞ 结语
```

## 第三步：文风规范（硬核派标准）

- **自然有温度**：不要官腔、不要营销号腔。用「我们」而不是机构名自称。
- **朋友口吻**：像跟朋友说话，但内容扎实。
- **段落 3-5 句**：不流水账，不堆砌。
- **emoji 克制**：板块标记用 emoji（🎨💡🏘️🎓），但不要每句都加。
- **金句提炼**：文章一定要有 1-2 个让人记住的金句（用引言卡或深色竖条引用块突出）。
- **标题 20 字内**：爆款向、去专业术语（如「zine」说「杂志风」），动词开头+具体结果更好。不吹不擂，事实本身有说服力。
- **不要锁死数量**：如果活动有 6 个上台+8 个海报区，标题不要写「六个」——写「十几个」或省略数量。
- **标题风格参考**（第二期爆款）：「椅子全搬空！这场广州 AI 公益课凭啥吸引100+人到场？」——用现场感钩子+具体数字。

## 第四步：排版规范（石墨极简 + 品牌黄）

**排版一律用石墨极简主题 + 硬核派品牌黄。** 组件从 `references/theme-graphite-minimal.md` 和 `references/common-components.md` 取，**不手写样式**。

### 核心规范
- 品牌黄 `#FFFB00` 全篇 ≤3 处（引言卡金句/结语锚点）
- 石墨下划线（`border-bottom:2px solid #52525B`）标记每段关键词（1-3 个/段）
- 石墨竖线（`border-left:3px solid #52525B`）做小标题
- 深色竖条引用块放核心金句
- 数据卡/药丸标签/时间线按内容选用（从组件库取）
- 深色块（如 QUOTE 引言卡）风格统一

### 排版流程（严格执行）
1. 从组件库取组件拼装 HTML（每段文字用 `<span leaf="">` 包裹）
2. 跑校验：`python3 scripts/validate_gzh_html.py <文件>` → **必须 0 ERROR**
3. 生成预览：`python3 scripts/wrap_preview.py <文件>` → 得到带「复制到公众号」按钮的预览页
4. 交付：预览页链接 + 说明「点右上角复制→粘贴到公众号编辑器」

### 署名规范（用户明确要求）
- **一律不署名**——不写「撰稿：XXX / 指导：XXX」，文章到 END 线就结束。
- 商务合作/招商类也不署名。

## 第五步：交付检查清单（发出去前逐项过）

- [ ] 素材已逐字读（含妙记智能章节/逐字稿），不是只看总结
- [ ] 人名准确（以用户确认名单为准）
- [ ] 活动时间/地点/数据准确
- [ ] 标题 ≤20 字、无专业术语、不夸大
- [ ] 有金句（引言卡或引用块）
- [ ] 段落 3-5 句，朋友口吻，无官腔
- [ ] emoji 克制使用
- [ ] 结构完整（引言→正文→结语→END线）
- [ ] 结尾有「感谢+引导」（活动回顾类：感谢主办方/嘉宾+引导关注）
- [ ] 排版：品牌黄 ≤3 处、石墨下划线每段、引用块金句
- [ ] 校验脚本 0 ERROR 通过
- [ ] 不署名

## 收官期/特殊节点处理

- **系列收官**（如第三期结束）：结尾要「不一样」——回顾整个系列的成长线（第一期认识→第二期使用→第三期创造），升华主题，加「这一季圆满结束，期待下一季，我们以后再见 🌟」类收尾。
- **内容单薄时**：从素材里挖更多细节（真实案例、具体数字、导师原话、工具清单），整理成「课后笔记」式分享，而不是只写活动概况。

## Common Pitfalls

1. **只看总结不读逐字稿**——用户明确批评过，这是写出好内容的头号敌人。
2. **人名写错**——语音转文字人名必错，必须确认（木木=木晓瑾、冠子=赛博罐子）。
3. **标题锁死数量**——活动项目多时不要写「六个」，写「十几个」。
4. **官腔/营销号腔**——「赋能」「打造」「生态闭环」这类词少用，自然说话。
5. **内容单薄**——只有活动概况没有细节。要挖案例、数字、金句、实操。
6. **排版偷懒**——全篇 callout 或纯文本平铺都不行，必须按组件库规范。
7. **markdown 符号进正文**——飞书/公众号不解析 `**`，必须用组件样式（span leaf）。
8. **署名**——一律不署名，别加「撰稿：XXX」。

## Verification

- 交付前跑 `python3 scripts/validate_gzh_html.py <文件>`，0 ERROR
- 对照「交付检查清单」逐项自查
- 让另一位小伙伴（非原作者）按本 skill 写一篇，对比风格是否一致
- 用完后如果发现需要调整的地方，记录到本文档「更新日志」部分，让规范持续演进

## 第六步：用样例校准 + 评测验证（借鉴 TRAE skill 规范）

1. **写之前/写完后对照** `examples/quality-cases.md`：

   - 坏样例自查：有没有锁数量、官腔、写错名、内容单薄、markdown 符号
2. **修改 skill 后跑** `evals/evals.md` 评测集（3 个 case），确认没改坏原本会做的事情
