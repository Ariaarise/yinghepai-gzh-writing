# 硬核派公众号写作标准（团队共享）

> 目标：让硬核派的任何一位小伙伴写公众号文章，都能达到阿梨同款质量——排版、格式、内容风格完全统一。本 skill 是「写作方法论」层，排版执行交给 gzh-design skill。

## When to Use

- 硬核派团队任何人要写公众号文章（活动回顾/工具推荐/人物采访/赛事公告/合作宣传）
- 写出来的文章被评价「不像硬核派的风格」「排版不对」「内容单薄」
- 需要把活动素材（逐字稿/智能纪要/现场照片）变成公众号文章

**Don't use for：** 小红书图文、抖音脚本、飞书内部文档（各有其他 skill）

## 第一步：素材处理（写之前必须做）

1. **逐字读素材，不只看总结**——如果活动有飞书妙记/智能纪要，必须打开妙记页面看「智能章节」（每段都有详细摘要），有条件就看完整逐字稿。用户明确强调过：「一定要逐字去看，不要只看总结，要看妙记里面的逐字稿」。这是写出好内容的前提。
2. **妙记访问技巧**：妙记 API 常缺 minutes 权限（99991672 错误），但**妙记网页本身可公开访问**——用 Playwright 打开妙记链接，点「Show More」展开纪要，点「Transcript」标签加载逐字稿，滚动触发懒加载，`document.body.innerText` 即可拿到全文。智能章节（Smart chapters）覆盖每个时间段的详细内容，即使逐字稿需登录也能拿到足够素材。**完整脚本见 `references/feishu-minutes-scrape.md`**。
3. **系列文章先读前作**：写系列的第 N 期（如图书馆第三期）前，先向用户要已发布的前几期公众号链接（mp.weixin.qq.com），抓取阅读对齐风格与结构——用户会拿前作当基准评价新文。抓取方法：curl + iPhone UA + 正则提取 `js_content`。
4. **提取关键信息**：活动时间地点、嘉宾名单（名字必须准确！语音转文字人名常错，以用户最终确认为准）、每个分享者的项目/主题/核心观点、现场互动、颁奖、照片素材。
5. **人名与称呼准确铁律**：语音转文字识别的人名经常错（如「韦神」变「维优」、「黄宇厦」变「黄宇尚」）。写之前向用户确认准确名单，或按用户最新提供的名单为准。**导师在社群中的称呼也要按用户确认**——例如「木木」实际是「木晓瑾」、「冠子」实际是「赛博罐子」，全文统一。
6. **品牌名/机构名不能写错**：用户对品牌名错误零容忍（「趣玩科技」实为「趣丸科技」被点名批评）。写完后全文搜索核对品牌名、机构名、产品名。
7. **整理成结构化笔记**：按「开场→各分享者→现场环节→收官」的顺序整理素材，标出哪些是亮点细节（金句、数据、真实案例）。

## 第二步：确定文章类型与结构

### 类型 A：活动回顾（最常见）
**结构模板（按此顺序）：**
```
QUOTE 引言卡（金句，从活动里最有张力的一句话提炼）
前言（活动时间地点+主题+一句话概述）
01 分享者/环节（每人或每环节一小节，详写核心内容）
02 现场互动/问答（有趣的问答、现场反应）
03 颁奖/特殊环节
∞ 结语（升华主题 + 感谢主办方/嘉宾 + 引导关注）
END 线（不署名——用户要求一律不署名，见第四步）
```

### 类型 B：工具/内容推荐
```
引言卡（痛点或钩子）
01-04 每个工具：适合什么 / 内容 / 特征
结尾：引导互动（「你最想拿哪个试试？评论区告诉我」）
```

### 类型 C：人物采访/特稿
```
引言卡（被访者金句）
01 认识 TA（背景介绍）
02 成长线/经历脉络
03 方法/干货
04 快问快答
∞ 结语
```

## 第三步：文风规范（阿梨标准）

- **自然有温度**：不要官腔、不要营销号腔。用「我们」而不是机构名自称。
- **朋友口吻**：像跟朋友说话，但内容扎实。
- **段落 3-5 句**：不流水账，不堆砌。
- **emoji 克制**：板块标记用 emoji（🎨💡🏘️🎓），但不要每句都加。
- **金句提炼**：文章一定要有 1-2 个让人记住的金句（用引言卡或深色竖条引用块突出）。
- **标题 20 字内**：爆款向、去专业术语（如「zine」说「杂志风」），动词开头+具体结果更好。不吹不擂，事实本身有说服力。
- **不要锁死数量**：如果活动有 6 个上台+8 个海报区，标题不要写「六个」——写「十几个」或省略数量。
- **公众号描述/摘要 = 极简留白**：用户明确参考过大 V 摘要风格（请辩「个人选择和努力到底有没有用？」、刘润「如题。」、上升期「不要回应。」）——摘要**不是复述内容**，而是 15 字内的悬念/态度/留白。活动回顾类的推荐格式：「从认识 AI，到创造 AI。」这类短句，或一句有张力的判断。

## 第四步：排版规范（对接 gzh-design）

**排版一律用 gzh-design skill 的石墨极简主题 + 硬核派品牌黄：**
- 加载 gzh-design，用「石墨极简(graphite-minimal)」主题
- 品牌黄 `#FFFB00` 全篇 ≤3 处（引言卡金句/结语锚点）
- 石墨下划线标记每段关键词（1-3 个/段）
- 深色竖条引用块放核心金句
- 数据卡/药丸标签/时间线按内容选用
- 署名区：**一律不署名**——用户明确要求「以后最后都不要署名」（不写撰稿/指导）。文章结尾到 END 线就结束。
- 商务合作/招商类不署名

**排版流程（严格执行）：**
1. 写正文 HTML（从 gzh-design 组件库取组件，不手写）
2. 跑校验：`python3 <gzh-design路径>/scripts/validate_gzh_html.py <文件>`
3. 生成预览：`python3 <gzh-design路径>/scripts/wrap_preview.py <文件>`
4. 交付：预览页链接 + 说明「点复制→粘贴到公众号」

## 第五步：交付检查清单（发出去前逐项过）

- [ ] 素材已逐字读（含妙记智能章节/逐字稿），不是只看总结
- [ ] 人名准确（以用户确认名单为准）
- [ ] 活动时间/地点/数据准确
- [ ] 标题 ≤20 字、无专业术语、不夸大
- [ ] 有金句（引言卡或引用块）
- [ ] 段落 3-5 句，朋友口吻，无官腔
- [ ] emoji 克制使用
- [ ] 结构完整（引言→正文→结语→END 线，无署名）
- [ ] 结尾有「感谢+引导」（活动回顾类：感谢主办方/嘉宾+引导关注）
- [ ] 排版：品牌黄 ≤3 处、石墨下划线每段、引用块金句
- [ ] 校验脚本 0 ERROR 通过
- [ ] 无署名（用户要求一律不署名，正文到 END 线结束）

## 收官期/特殊节点处理

- **系列收官**（如第三期结束）：结尾要「不一样」且**写长**（用户明确要求「收官你写长一点」）——① 总结整个系列的成长线（第一期认识→第二期使用→第三期创造，每期一句话回顾）；② **画面感优先**：每期配一个具体场景画面（如第一期长者认真记笔记/孩子第一次做网页、第二期人满到搬长椅、第三期人人拿到证书）——用户两次嫌「收官单薄」，加了画面感才通过；③ 展望未来（后续活动预告）；④ 大力感谢：主办方（如图书馆，从场地到组织的支持）、所有分享导师（点名）、每一位到场的朋友。用「江湖再见」或「愿你我心中皆有焰火」类收尾。
- **互动/问答段落泛化**：现场提问的具体案例不要写太细——用户明确嫌「下水道科普视频」这种例子「好奇怪」要求泛化。写法：保留「有人提出 XX 类问题→导师现场给方法→课后继续答疑」的通用结构，具体示例一笔带过或替换成「生活科普视频」这类普遍例子。
- **合作方串联**：当现场分享提到某产品/工具，而硬核派与该品牌有过往合作（如趣丸科技 Tunee 的世界杯 AI 音乐大赛）时，加一小段点明「这正是 XX 在做的事 + 我们合作过 XX」——借势安利合作方，也增强文章与社群记忆的呼应。品牌名必须精确（趣丸科技≠趣玩）。
- **内容单薄时**：从素材里挖更多细节（真实案例、具体数字、导师原话、工具清单），整理成「课后笔记」式分享，而不是只写活动概况。
- **实操/教学段落的小标题**：用「▎」符号做视觉锚即可，**不要同时加 border-left 竖条**——两者叠加视觉冗余（用户明确指出「有一条竖线就好了」）。小标题样式：`font-weight:800` 深炭色即可，不带左边框。

## Common Pitfalls

1. **只看总结不读逐字稿**——用户明确批评过，这是写出好内容的头号敌人。妙记智能章节要展开看，逐字稿能拿就拿。
2. **人名写错**——语音转文字人名必错，必须确认。
3. **品牌名/机构名写错**——用户零容忍（「趣玩」应为「趣丸科技」）。交付前全文搜索品牌名。
4. **标题锁死数量**——活动项目多时不要写「六个」，写「十几个」。
5. **官腔/营销号腔**——「赋能」「打造」「生态闭环」这类词少用，自然说话。
6. **内容单薄**——只有活动概况没有细节。要挖案例、数字、金句、实操。
7. **排版偷懒**——全篇 callout 或纯文本平铺都不行，必须按 gzh-design 规范（真表格/引用块/下划线层级）。
8. **markdown 符号进正文**——飞书/公众号不解析 `**`，必须用组件样式。
9. **小标题竖线冗余**——`▎` 符号和 border-left 竖条不要同时用，留一个即可。
10. **现场案例写太细**——互动/问答段的具体例子（如「下水道科普视频」）会让读者觉得奇怪，泛化成通用描述（「生活科普视频」）。
11. **收官干瘪**——只用抽象总结（「回望三期，见证成长」）会被嫌单薄，必须配具体画面（谁在做什么/什么场景）才有感染力。
12. **误解用户发来的公众号链接**——用户发 mp.weixin.qq.com 链接不一定是要「参考风格」：可能是定时任务里待沉淀的文章（发 3 篇让我存 Obsidian）、过往合作文章（趣丸世界杯大赛）、或前几期系列文。**先确认意图（问一句或查上下文）再行动**，不要默认当成「摘要风格参考」去研究——本次把 3 篇待沉淀文章当成摘要风格研究，方向完全错了。
