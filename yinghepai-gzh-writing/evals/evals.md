# 硬核派公众号 skill · 评测集（20 case + 评分维度）

> 每次修改 skill 后，跑评测确认没改坏。评测不只判断「能不能跑」，还要**自动评分**。

---

## 评分维度（总分 100）

| 维度 | 分值 | 看什么 |
|------|------|--------|
| 事实准确性 | 25 | 人名/数字/时间/地点 vs FACT SHEET，有无越界推断 |
| 内容完整性 | 20 | 该有的都有（活动信息/嘉宾/现场/结尾），不单薄 |
| 硬核派文风 | 20 | 过 style-anatomy：禁词/AI味/段落节奏/具体细节 |
| 结构 | 15 | 符合类型模板，引言→正文→结尾完整 |
| 标题 | 10 | 符合类型策略，≤20字，不夸大 |
| 排版 | 10 | 品牌黄≤3处、span leaf、组件比例、校验0 ERROR |

## 20 个固定 Case

### Case 1：普通活动回顾（标准）
**输入：** 一场活动的基本素材（时间/地点/3位嘉宾/现场互动/合影）。
**预期：** 引言卡金句 + 嘉宾详写 + 现场 + 致谢；FACT SHEET 完整。

### Case 2：嘉宾很多（>6位）
**输入：** 一场活动 8 位分享者素材。
**预期：** Editorial Judgment 生效——不是平均分配，突出 2-3 位最值得写的，其余合并提。

### Case 3：活动素材很少
**输入：** 只有「活动圆满举办，3位导师分享，气氛热烈」这句话。
**预期：** 触发素材不足检测 → 向用户询问细节，不硬写。

### Case 4：逐字稿非常长（>4万字）
**输入：** 3 小时活动逐字稿。
**预期：** 语义分段提炼，FACT SHEET 提取，不罗列全文。

### Case 5：人名错误
**输入：** 语音转文字把「木晓瑾」写成「木木」。
**预期：** 标记待确认 → 使用正确人名（或询问用户）。

### Case 6：数字冲突
**输入：** 素材 A 说 100 人，素材 B 说 200 人。
**预期：** 列出矛盾询问用户，不自行选择。

### Case 7：没有金句
**输入：** 素材里没有出彩原话。
**预期：** 不硬造金句；用 EDITORIAL_QUOTE 概括，不用引号伪装。

### Case 8：有大量营销话术
**输入：** 素材充满「赋能/闭环/生态」。
**预期：** style-anatomy 禁词表过滤，改写为具体表达。

### Case 9：工具推荐
**输入：** 一款 AI 工具的评测素材。
**预期：** 痛点开头 + 适合什么/内容/特征 + 互动结尾。

### Case 10：人物专访
**输入：** 对一位创作者的采访记录。
**预期：** 金句开场 + 成长线 + 干货 + 快问快答。

### Case 11：赛事公告
**输入：** 一场比赛的规则/奖项/时间。
**预期：** 活动名 + 动作 + 时间节点标题；规则清晰呈现。

### Case 12：合作宣传
**输入：** 硬核派 × 某品牌的合作活动素材。
**预期：** 品牌+事件标题；致谢合作方；不夸大。

### Case 13：只有海报
**输入：** 只有一张活动海报（无文字素材）。
**预期：** 素材不足检测 → 询问，不编造内容。

### Case 14：只有活动总结（纪要）
**输入：** 只有 AI 生成的会议纪要，无逐字稿。
**预期：** 标记「证据不足」，说明哪些内容不确定，写前确认。

### Case 15：只有逐字稿
**输入：** 只有逐字稿无其他素材。
**预期：** 从逐字稿提取事实，人名标注待确认。

### Case 16：多个来源互相冲突
**输入：** 逐字稿说 A 嘉宾讲的，纪要说是 B 讲的。
**预期：** 列出冲突，询问用户。

### Case 17：嘉宾说了不确定的信息
**输入：** 嘉宾说「我听说千问要出 XX 功能」。
**预期：** 标记为「嘉宾观点/传闻」，不写成官方信息。

### Case 18：需要删减长文
**输入：** 已有 3000 字初稿，需要 800 字。
**预期：** Editorial Judgment——保留最有价值的，允许删除 50%+。

### Case 19：已有初稿需要改写
**输入：** 一份 AI 味很重的初稿。
**预期：** 走改写模式：过禁词表、去 AI 味、改段落节奏。

### Case 20：已有 HTML 需要重新排版
**输入：** 一篇纯文本文章需要排版。
**预期：** 只走 Design 层——组件选择矩阵 + 70/20/10 + 校验。

## 评测方法

1. 修改 skill 后，选相关 case 跑一遍（重大修改跑全部 20 个）
2. 按评分维度打分（事实25/内容20/文风20/结构15/标题10/排版10）
3. 总分 ≥85 = 通过；<85 = 找出失分项，修复后重跑
4. 记录到下方日志
