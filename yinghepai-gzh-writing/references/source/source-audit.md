# Source Audit（素材审计）

> **写作的第一步不是「理解素材」，而是「审计素材」**——先摸清手里有什么、缺什么、哪里冲突，再决定能不能写、怎么写。

## 审计输出模板（内部工作结构，写入后留存）

```markdown
## SOURCE AUDIT

### 来源清单
| # | 来源 | 类型 | 可读取? | 完整度 |
|---|------|------|--------|--------|
| 1 | 飞书文档 A（活动纪要）| 纪要 | ✅ | 85% |
| 2 | 采访逐字稿 B | 逐字稿 | ✅ | 100% |
| 3 | 海报图片 | 海报 | ⚠️ 需OCR | 40% |

### 已确认事实（可直接用）
- ✅ 活动名称：
- ✅ 时间：
- ✅ 地点：
- ✅ 嘉宾名单：
- ✅ 活动流程：

### 缺失项（不可用，需补齐或标记）
- ⚠️ 参与人数（来源 A/B 都没写）
- ⚠️ 嘉宾身份（只有名字没有头衔）
- ⚠️ 部分项目名称

### 冲突项（必须处理）
- ⚠️ 来源 A 说 200 人，来源 B 说 180 人 → 问用户 or 用「约200人」
- ⚠️ 人名「木木」vs「木晓瑾」→ 以用户确认为准

### 可引用原话（DIRECT QUOTE）
- ✓ "XXX" —— 来源 B / 00:18:32
- ✓ "XXX" —— 来源 A / 第 3 段

### 风险等级
- 🟢 低：素材充分，可正常写作
- 🟡 中：有缺失/冲突，写前标记，缺失处不写
- 🔴 高：素材严重不足 → 走 INPUT GATE，STOP 要素材
```

## 审计规则

1. **先列来源清单**——到底有几个来源、各是什么类型、能不能读
2. **区分「已确认」和「缺失」**——能写的写，不能写的不写
3. **冲突必须处理**——两个来源数字不一样，不能自己选一个，要标记/问用户
4. **人名低可靠来源 → 标待确认**（语音转文字必错）
5. **风险等级决定行为**：
   - 🟢 → 正常走流程
   - 🟡 → 缺失处跳过，冲突处问用户
   - 🔴 → STOP，要求素材

## 飞书来源的标准入口（未来接 Connector）

```
用户发飞书链接
  ↓
1. 获取飞书文档（API/Playwright）
2. 判断是否可读取（权限检查）
3. 提取正文
4. 检查附件/图片/表格
5. 建立 SOURCE MAP
6. 提取事实
7. 进入写作
```

**禁止：拿到 URL → 直接让 LLM 总结 → 开始写。（没有经过审计的事实链，写出来的不可信）**
