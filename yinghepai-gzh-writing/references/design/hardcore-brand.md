# 硬核派品牌定制（gzh-design 本地化）

记录 gzh-design skill 在硬核派公众号场景下的本地化定制。改主题库/排版前先读这里。

## 安装方式（GitHub raw 直连不稳）

- 必须 `git clone --depth 1 https://github.com/isjiamu/gzh-design-skill`（curl 单文件拉 raw 会超时/截断）
- clone 后把 `assets/`（含 preview-template.html，wrap_preview.py 依赖）、`scripts/`、`references/` 全部拷到 skill 目录，否则预览页生成报 FileNotFoundError
- 校验：每次排版后跑 `scripts/validate_gzh_html.py <html>`，ERROR 清零 + WARNING 人工确认（图片占位符未包 span leaf 的 WARNING 属正常，换真图即消）

## 品牌主色

- 品牌黄：`#FFFB00`（rgb(255,251,0)）— 替换主题库默认强调橙 `#F97316`
- 已修改 `references/theme-graphite-minimal.md`：所有 `#F97316` → `#FFFB00`（含文字「暖橙/橙色」→「品牌黄」）
- 用途：金句竖条（border-left 黄 + 淡黄渐变底 `linear-gradient(90deg, rgba(255,251,0,0.10-0.12), transparent)`）、关键词下划线点睛、CTA 锚点
- 配额：沿用原主题「锚点层 ≤3 处」逻辑，黄只出现在最关键处

## 赛事/活动专属色系（用户给色卡时优先用官方色系）

⚠️ **色系适用范围铁律（用户明确纠正）**：官方赛事色系**只在「该赛事/活动相关文章」用**——如 AIGC ASIA 大赛的赞助方案、大赛推文。**普通文章（工具推荐、日常推文等）一律用硬核派品牌黄 `#FFFB00`**，不要因为上一篇文章用了赛事色系就惯性沿用（实操教训：Zine Skill 推荐文误用赛事色系被纠正「这个 AIGC ASIA 官方色系只有我提到相关的活动的时候需要提到，一般的文章不需要提」）。开工前先判断：这篇文章是否属于该赛事/活动。

⚠️ 用户明确反馈过：**纯 `#FFFB00` 大面积用会刺眼、显廉价**——「黄是对的，但纯黄不对」。当用户提供某赛事/活动的**官方色卡**时，该赛事相关文章改用官方色系，而不是硬核派默认黄。示例（AIGC ASIA 赛事官方色系）：

| 颜色 | 色值 | 用途 |
|------|------|------|
| BRIGHT YELLOW | `#FFD600` | 主强调色：金句、CTA、首席卡 |
| ELECTRIC BLUE | `#0066FF` | 点缀色：章节英文标签、数据权重、引言标签 |
| VIVID RED | `#FF2020` | 点睛（全篇 ≤1-2 处）：最高档金额等 |
| PURE BLACK | `#000000` | 标题、深色卡底（比 #27272A 更有品牌感） |
| PURE WHITE | `#FFFFFF` | 背景 |

**获取色卡方式**：用户发色卡图但环境无视觉模型时，用 PIL 分段统计主色（`Image.crop` 横向切片 + 平均色），或直接请用户文字给出官方色值（HEX/CMYK）。**用户给文字色值优先采用（比图片提取准）**——实操案例：AIGC ASIA 色卡图片提取出的近似色（#D5B105 暗金、#0549CE 深蓝）被用户纠正，用户直接给了官方色值（黄 #FFD600 / 蓝 #0066FF / 红 #FF2020 / 黑 #000000 / 白 #FFFFFF）。色卡图提取只是兜底，永远优先要文字版官方色值。

**⚠️ 多轮配色时用「旧色 → 新色」全量替换并核对残留**：配色反复调整时（如荧光黄→暗金→官方黄），用脚本统一替换后必须再查一遍旧色值残留（`html.count('#FFFB00')` 等），包括渐变里的中间色（如奖牌渐变 #FFD700）——漏掉一处旧色会破坏整体统一。

**渐变卡片高级感套路（用户明确要求「多多运用颜色、弄出渐变、非常高级的品牌效果」）**：
- **并列卡片组按品牌色依次排布**（黄→蓝→红→黑），每张卡独立渐变：`linear-gradient(135deg, 主色 0%, 浅色 55%, 更浅 100%)` + 同色系光晕阴影 `box-shadow:0 6px 20px -6px rgba(主色,0.5)`
- 深色卡（蓝/红/黑底）用白字；亮色卡（黄底）用黑字
- 示例：赞助档位四卡 = 首席(黄金渐变/黑字) → 战略(电光蓝渐变/白字) → 赞助(鲜红渐变/白字) → 支持(黑灰渐变/白字)；评审权重四卡、品牌回报六宫格同理
- **六宫格/多卡组别全彩**：全彩 6 张会花——改用「顶部品牌色条（3px）+ 淡色渐变底 + 同色小字编号」，克制又统一
- 关键词高亮：荧光黄 `linear-gradient(transparent 55%, #FFD600 55%)` 做文字底部高亮（5000 万+ 这类关键数字）
- 章节水印编号仍用浅灰 #E4E4E7（装饰层不抢戏），英文标签用点缀色（蓝）

## 视觉识别（识别图片内容/色卡时）

- 服务器无 GPU 且内存小（如 3.6GB）时 Ollama 本地模型会段错误（exit 139/126），**不要在这上面耗时间**
- 快速路径：免费视觉 API——**智谱 GLM-4V-Flash**（open.bigmodel.cn 注册，官方免费）或硅基流动 SiliconFlow；OpenAI 兼容格式 `chat/completions` + `image_url` base64 即可
- 用户注册好 key 后可直接调；没 key 时就用 PIL 统计色/问用户文字版色值兜底（见上）

## 图片插入（gzh-design 排版时）

- **图片要能显示，必须 base64 内嵌**：相对路径（`assets/xxx.jpg`）在预览页里显示不出来（用户反馈「我丢 没有图啊」）。把图片转 `data:image/jpeg;base64,...` 内嵌进 `<img src>` 即可在预览页显示
- 公众号粘贴时图片仍需在公众号后台重新上传（微信不认外部路径/base64），预览页只用于看效果
- 无法确认图片内容时（环境无视觉模型）**不要硬插**：用户宁愿纯文字排版，也不要猜错位置的图。先问用户每张图放哪，或用能确定的图（如封面主视觉、饱和度明显更高的实景照）
- **用户可能最终放弃插图**（实操案例：AIGC ASIA 赞助方案，图片插入后用户说「不需要你插入图片了，弄回纯文字和排版」）——图片素材不确定或用户忙时，默认纯文字排版 + 高级配色即可，插图等用户明确要求再做
- Keynote（.key）文件里的图片：先 unzip 解出 Data/ 目录，用 MD5 与用户单独发的图比对可确认同源；IWA 幻灯片索引是 protobuf 压缩二进制，strings/正则搜不到中文与图片引用，别在这上面浪费时间——直接问用户每张图放哪

## 常用主题选择

- 政务/正式合作文 → 石墨极简（graphite-minimal）
- 教程/清单/工具盘点 → 摸鱼绿（moyu-green）
- 深度观点/力量感话题 → 红白色系（red-white）

## 文章结构约定（正式合作文）

```
正文章节（01/02/03 水印编号）
→ 招商/企业服务板块（04）
→ 致谢 OUTRO（情绪收尾，无编号标签或纯正文）
→ 署名区（右对齐）
```

⚠️ **顺序铁律：招商 CTA 必须在致谢之前。** 内容讲完 → 抛出合作邀请（行动号召）→ 感谢收尾（情绪落点）→ 署名。致谢之后再出现招商会情绪断裂（用户明确反馈过 OUTRO 放 04 前面「怪怪的」）。

## 署名区（组件 16b，右对齐）

- 右对齐、辅助灰小字（#A1A1AA）、12px、letter-spacing 1px、行高 1.8
- 默认格式两行：`撰稿：阿梨` + `指导：巴斯`
- 约定：**同一个人只出现一次**（阿梨=撰稿，不再重复写摄影/排版）；指导=巴斯
- 字段按实际参与人增删，无字段整行删除；全部未知则整块删

## 企业服务板块（标准文案，可复用）

标题：硬核派 AI 生态与企业服务（04 ECOSYSTEM）
- 定位方向：AI 社区、活动运营、产品营销、自媒体传播、企业培训
- 企业服务：AI 营销增长、品牌传播、用户运营、活动策划及人才培养
- 愿景句：持续连接产业需求与 AI 创新力量
- CTA 条（黄色竖条）：📄 企业合作资料 — 扫码/后台回复「XX」领取硬核派企业 AI 服务介绍（关键词随文章定制，如「越秀」）

## 排版红线（用户逐条确认过）

- **HTML 只输出正文内容，不要大标题**（文章标题在公众号后台单独填）
- **分割线要短**：1px 细线（#E4E4E7），不要通栏长条；正式文可干脆不用分割线，靠留白分段
- 正式为主 + 活人感：可引一句当事人原话做点睛（如领导金句用黄色竖条突出）
- **政策/合作细节模糊化**：对未敲定的事项用「表示/希望/探讨/期待」，不写具体项目名、不写具体数字；目的是传达「被看好、愿支持」而不是「已敲定」
- 正文关键词下划线标记（石墨灰 `border-bottom:2px solid #52525B`），每段 1-3 处
- 生成后必须跑 `scripts/validate_gzh_html.py`，并生成带复制按钮的预览页 `scripts/wrap_preview.py`（assets/preview-template.html 需存在）
- **不要手写样式**：用户曾评价手写 HTML「设计很不好看」——一律从主题组件库取组件，不要凭记忆手写 CSS

## 输出交付

- 干净正文 HTML：`{文件名}_排版_{主题中文名}({英文标识}).html`
- 预览页：`{...}_预览.html`，告知用户「浏览器打开 → 右上角复制 → 公众号粘贴」
- 图片占位用 `【图N：描述】`，校验脚本会把未包 span leaf 的占位报 WARNING（属正常，换真图即消）
